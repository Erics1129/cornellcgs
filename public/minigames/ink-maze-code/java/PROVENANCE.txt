Ink Maze level 26 — Java runtime provenance
============================================

What runs the player's Java
---------------------------
TeaVM-javac: OpenJDK's javac (Java 25 language level) and the TeaVM 0.13.1
ahead-of-time compiler, both compiled to WebAssembly GC by TeaVM, run inside
the sandbox's Java worker:

  Solution.java --javac--> class files --TeaVM (+ GuardTransformer)--> app.wasm

The hidden harness (InkMazeHarness.class, compiled ahead of time) is the
entry point; javac never sees it. Every Run instantiates app.wasm afresh.
Nothing is loaded from a CDN: the page serves every file below to the sandbox.

The site's patch (teavm-javac-inkmaze.patch)
---------------------------------------------
  guard/Guard.java             the cooperative deadline and allocation meter: static methods that
                               call the "inkGuard" imports (check, limit, memory, exit), plus
                               Java-semantics helpers (index, idiv, irem, ldiv, lrem).
  guard/GuardTransformer.java  a TeaVM ClassHolderTransformer. PROGRAM mode (installed by
                               Compiler.generateWebAssembly for every program, last): Guard.tick()
                               at every loop header (back-edge target, exception edges included),
                               at the entry of every method that calls anything and every 256
                               instructions; Guard.work(n) before System.arraycopy; Guard.alloc*
                               before every allocation (objects by field count, +4 KiB for a
                               Throwable, +512 B for a Reference, +1 KiB for a Thread; arrays,
                               multi-dimensional arrays, clones, reflect.Array.newInstance);
                               Guard.exit in place of System.exit / Runtime.exit / Runtime.halt;
                               in the player's classes (unnamed package) Guard.index before every
                               array element access; integer division / remainder by a
                               non-constant through Guard.idiv & co. COMPILER mode (installed by
                               Patches while TeaVM builds the compiler itself): ticks, allocations
                               and divisions in javac and TeaVM, so compiles stop at their deadline
                               and memory budget (and javac no longer traps on MIN_VALUE / -1).
                               Runtime support is never instrumented: org.teavm.runtime, .interop,
                               .jso, .platform, *.runtime.* and the Guard (COMPILER mode also leaves
                               out .classlib.impl). In PROGRAM mode the class library's helpers in
                               org.teavm.classlib.impl ARE instrumented (since 2026-10-13): they are
                               ordinary Java the player drives through java.*, e.g. java.util.Base64
                               runs its whole loop and allocates its result in Base64Impl. Left out,
                               a Base64 bomb grew WebKit to 4.5 GB unmetered, ran past the deadline
                               into the host backstop and kept a core busy after terminate().
  WasmBodyPatch.java + Patches a non-void method that can never return (a loop with no exit)
                               made a function body without its result, which every engine
                               rejects; a non-void body that ends with a statement now gets
                               `unreachable` after it (applied to WasmGCMethodGenerator by Patches).
  StdlibConverter.java         javac sees System.exit(int) (TeaVM's System has none).
  Compiler.java                guard option (default on); compile() starts a fresh javac even when
                               the previous compile was stopped mid-way.
  JavaDiagnostic.java          fileName is null for a diagnostic without a source (a note), not a trap.
  TeaVMDiagnostic.java         the rendered message, not the {{m0}} template.
  WebAssemblyCompilationOptions.java, Worker.java   the guard option.
  build.gradle                 runtime-classlib.bin also carries org/teavm/javac/guard/Guard.class.

The limits runtime.js applies through the guard
-----------------------------------------------
  time        io.check() at least every 16,384 ticks (a tick: a loop header, a call, 256 instructions,
              1,024 copied elements, 4 KiB allocated, 64 Throwables); a program stops itself at its
              deadline, catch blocks cannot hold it (TeaVM catches only its Java exception tag)
  memory      one allocation <= job.memoryLimitBytes (256 MiB); everything allocated in a run <= 2x
              that (512 MiB, garbage included); javac may allocate 384 MiB and TeaVM 6 GiB per compile (garbage included; a
              typical solution: TeaVM 0.5-0.6 GiB, a program that pulls in String.format, BigInteger,
              regex, streams and most collections 2.7 GiB, which the old 2 GiB budget refused)
  output      io.stdout / io.stderr (the output limit); answers go through the harness's own import
  after a limit  a run stopped by its deadline or the output limit keeps the worker; memory_limit and
              any limit while compiling replace it (the guard may have stopped javac or TeaVM anywhere)

Rebuild
-------
  JAVA_HOME=<Temurin 25> sh scripts/inkmaze-code/build/java/build.sh
(downloads the archive above and checks its hash, applies both patches, runs
`./gradlew --no-daemon :compiler:build -x test`, compiles the harness, gzips
compiler.wasm, copies the files here and prints their SHA-256). Two builds of
the same tree are byte-identical; a tree that once built other versions may
differ in a few hundred bytes of constants, so check a rebuild by function
(scripts/inkmaze-code/test-runtime-java.mjs), not only by hash.

Known class-library gaps (TeaVM 0.13.1; the same with and without the guard; the suite pins each
as a clean error): String.format / printf %f and %.2f (NullPointerException inside the library),
%n (UnknownFormatConversionException), EnumMap / EnumSet (NullPointerException: no enum constants
by reflection), Integer::sum and Collectors.groupingBy(f, mapFactory, downstream) (missing from
the compile class library: javac says cannot find symbol / incompatible types).
