Ink Maze level 26 — Python runtime provenance
==============================================

What runs the player's Python
-----------------------------
Pyodide 314.0.7 (CPython 3.14.2 compiled to WebAssembly). Pyodide's own files
are NOT self-hosted: they load, only when the player picks Python, from the
pinned CDN
  https://cdn.jsdelivr.net/pyodide/v314.0.7/full/
  (pyodide.mjs, pyodide.asm.mjs, pyodide.asm.wasm, python_stdlib.zip,
   pyodide-lock.json)
which sandbox.html's Content-Security-Policy allows (script-src and connect-src
list exactly this prefix; the version is pinned in the path). First load
transfers about 6 MB (brotli). npm pyodide@314.0.7, published 2026-09-14.

Self-hosted here (the site's own code)
--------------------------------------
  runtime.js    the Runtime (src/minigames/inkmaze/code/contract.ts): loads
                Pyodide, caps the wasm heap, routes stdout/stderr to the run's
                io, installs a ONE-SHOT, self-disarming interrupt buffer (the
                getter returns SIGINT once past the deadline, then disarms so it
                cannot re-fire during cleanup), installs driver.py and runs the
                player's code.
  driver.py     compiles the player's code as solution.py and enforces the
                WebKit-safe cooperative deadline of contract D1-D9 three ways,
                because worker.terminate() does not stop a running wasm loop:
                 1. an AST pass that calls __ink_tick__ at every loop body,
                    function entry AND comprehension / generator-expression
                    iterable (so a `for ... in` driven by a C builtin still
                    ticks), raising a sticky, uncatchable _InkStop past the
                    deadline;
                 2. the runtime's interrupt buffer, which raises KeyboardInterrupt
                    at the next bytecode boundary so any C-driven bytecode loop
                    (genexp / comprehension / callable-iterator / key lambda)
                    stops; the driver disarms it the instant it catches the stop;
                 3. the pure-C library loops that take no bytecode per step are
                    bounded at the source: the O(1)-memory C consumers
                    (sum/any/all/max/min/sorted/math.prod/math.fsum/
                    functools.reduce/operator.countOf/collections.deque) and the
                    infinite sources (2-arg iter, itertools.count/cycle/repeat)
                    are wrapped to drive their input through a ticking generator;
                    math.factorial/comb/perm and pow() with a huge argument are
                    capped; sys.set_int_max_str_digits is clamped so int<->str
                    stays a ValueError; and the re / regex modules (catastrophic
                    backtracking has no Python back-edge) are refused. os.close
                    of fd 0/1/2 is refused so it cannot crash the interpreter.
                It restores the interpreter between runs (builtins, modules, the
                recursion limit, gc.callbacks, the fd streams, the C-surface
                wrappers), fingerprints the modules it relies on, runs end-of-run
                gc under the same deadline, and reports the outcome.
  harness.py    the hidden harness (problem.ts H1-H6): one Solution() per board,
                one "@@ANSWER@@ <moves>" line per board, escapeAnswer matched to
                problem.ts exactly.

Licences
--------
Pyodide is MPL-2.0; the bundled CPython and its C libraries are each under their
own licence (PSF, zlib, bzip2, libexpat, mpdecimal, liblzma/xz, HACL*, SQLite).
Because the compiled form is distributed to the browser, the MPL asks that the
source be findable: Pyodide 314.0.7 source is at
  https://github.com/pyodide/pyodide  (release tag 314.0.7)
Loading from jsDelivr means the CDN distributes those files; this note and the
top-level LICENSES.txt record the notices. The site's own driver.py, harness.py
and runtime.js are not covered by those licences.

Not shipped
-----------
The reference and naive solutions live in
scripts/inkmaze-code/solutions/python-{reference,naive}.py and are used only by
the tests; they are never served to the player.
